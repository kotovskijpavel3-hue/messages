# Messages Online

Одна ссылка — и вы в общем чате с файлами и шашками. Комнаты открываются по короткому коду, людей можно найти поиском по имени, а партию — начать в один клик.

## Что умеет

**Чат**
- Общая комната `MAIN` — все, кто открыл сайт, сразу в ней.
- Личные комнаты с кодом вида `ABC-123`: ссылка `/?room=ABC123` или ввод кода в сайдбаре.
- История на 200 сообщений, системные отметки о входе/выходе, индикатор «печатает…».
- Имя и цвет выдаются автоматически, имя можно поменять в шапке.

**Кто онлайн**
- Список всех подключённых с поиском по имени — видно, в какой комнате человек и играет ли он.
- `⚔` — вызвать на шашки, `✉` — пригласить в свою комнату.
- Приватные комнаты в общем списке не показываются: только свои и публичные.

**Файлы**
- Кнопка-скрепка, отдельная вкладка «Файлы» и drag & drop в окно.
- До 8 МБ на файл, 40 файлов и 120 МБ на комнату.
- Картинки показываются превью, остальное — карточкой с типом и размером.
- Скачивание по `/f/<id>/<имя>`; HTML и SVG отдаются только как вложение — чтобы никто не подсунул страницу на домен сайта.

**Шашки**
- Русские шашки: бой обязателен, простая бьёт в любую сторону, дамка ходит и бьёт «с лету», начатый бой доводится до конца, превращение — после завершения боя.
- Все ходы проверяет сервер: подсказки в интерфейсе только подсвечивают то, что разрешено.
- Вызов → принятие → партия; можно смотреть как зритель, сдаться, предложить ничью, сыграть ещё.
- Ничья автоматически после 60 полуходов без боя и без хода простой.

## Стек

- Одно ядро (`lib/hub.js`) и два тонких адаптера: Node (`server.js`) и Deno (`main.ts`).
- Node — `http` для статики и файлов + `ws` для WebSocket, без фреймворков.
- Deno — `Deno.serve` + `Deno.upgradeWebSocket`, без зависимостей вообще.
- Фронтенд — чистые HTML/CSS/JS, без сборки.
- Состояние — в памяти процесса.

## Запуск

Node:

```bash
npm install
npm start
```

Deno (без установки зависимостей):

```bash
deno run --allow-net --allow-env --allow-read main.ts
```

Открыть http://localhost:3000. Чтобы проверить мультиплеер, откройте вторую вкладку: сообщения, список людей и шашки работают между ними.

Тесты (правила шашек + полный сценарий через WebSocket):

```bash
npm test
```

## Структура

```
main.ts              Deno Deploy: Deno.serve + Deno.upgradeWebSocket, статика и файлы
server.js            Node: http-статика, раздача файлов, ws-сервер
lib/hub.js           вся логика: комнаты, чат, файлы, вызовы, партии
lib/checkers.js      правила русских шашек (чистые функции, покрыты тестами)
public/index.html    разметка: шапка, сайдбар, три вкладки
public/style.css     тёмная тема, мобильная вёрстка, доска
public/app.js        WebSocket-клиент, чат, файлы, поиск людей, вкладки
public/checkers.js   отрисовка доски и выбор хода
test/                node:test — правила и сквозной сценарий
render.yaml          деплой на Render
```

## Протокол WebSocket

Клиент подключается к `/?room=CODE&name=Имя` и получает `welcome` с комнатой, историей, списком онлайна и текущей партией.

| Клиент → сервер | Что делает |
|---|---|
| `chat {text}` | сообщение в комнату |
| `typing` | «печатает…» |
| `setName {name}` | смена имени |
| `createRoom {name, isPublic}` | создать комнату, сразу войти |
| `joinRoom {code}` / `leaveRoom` | вход по коду / назад в общий чат |
| `upload {name, mime, data}` | файл в base64 |
| `challenge {toId}` / `challengeReply {id, accept}` | вызов на шашки |
| `invite {toId}` | позвать в свою комнату |
| `gameMove {from, to}` | ход (одна пересадка при бое) |
| `gameResign`, `gameDrawOffer`, `gameDrawReply {accept}`, `gameNew` | сдача, ничья, реванш |

| Сервер → клиент | Что приходит |
|---|---|
| `welcome`, `room`, `message`, `online`, `rooms`, `game` | состояние и обновления |
| `typing`, `notice`, `challenge`, `challengeGone`, `invite` | события |

## Деплой на Deno Deploy

Конфигурация приложения лежит в `deno.json` — секция `deploy.runtime` объявляет динамическое приложение с entrypoint `main.ts`. Если эта секция есть, Deno Deploy берёт настройки из файла и игнорирует поля в дашборде.

Из CLI:

```bash
export DENO_DEPLOY_TOKEN=...
deno deploy . --org chees-online --app messages --prod
```

Проверка после деплоя: `/health` должен отдать `{"ok":true,"users":0,...}`. Если вместо этого 404, а `/` отдаёт HTML — приложение собралось как статический сайт, и чат работать не будет.

Важно: поле **App directory** в настройках приложения должно быть пустым, то есть корень репозитория. Если там указан файл (например `main.ts`), CLI падает с `Not a directory: realpath 'main.ts/deno.json'`, а сборка остаётся статической.

## Деплой на Render

### Blueprint

1. [render.com](https://render.com) → **New +** → **Blueprint**.
2. Выбрать репозиторий `messages` → **Connect** → **Apply**.

### Вручную

1. **New +** → **Web Service** → подключить `messages`.
2. Runtime **Node**, Build `npm install`, Start `npm start`, план **Free**.
3. Проверка живости — `/health`.

WebSocket работает на Web Service. Static Site не подойдёт: там нет серверной части.

## Ограничения

- Всё состояние в памяти: перезапуск сервиса очищает комнаты, сообщения, файлы и партии.
- Бесплатный план Render засыпает после ~15 минут без трафика; первый заход после сна — 30–60 секунд, WebSocket переподключается сам.
- Файлы не переживают рестарт и не хранятся на диске — это осознанно, чтобы не тащить базу и S3.
- Один аккаунт = одна вкладка = один участник; авторизации нет, имя можно любое.
- На Deno Deploy приложение может работать в нескольких инстансах: состояние в памяти у каждого своё, поэтому сообщения и список онлайна между инстансами не синхронизируются. Для одного инстанса используйте Render или VPS.
